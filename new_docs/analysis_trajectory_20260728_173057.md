## 3. 关键发现

### 3.1 编辑事件时间分布

```
t ∈ [0.0, 0.2):   0 events  (0%正确)   ← 模型从不提前编辑 (好)
t ∈ [0.2, 0.4):   9 events  (89%正确)  ← 早期编辑更准确
t ∈ [0.4, 0.6):  10 events  (80%正确)
t ∈ [0.6, 0.8):  29 events  (83%正确)
t ∈ [0.8, 1.0):  41 events  (78%正确)  ← 半数事件挤在最后 20%
```

**问题 1: 编辑事件过度集中在晚期。** 41/89 (46%) 的事件发生在 t>0.8。最后 20% 的时间承担了近一半的编辑量。这意味着：
- 前 80% 的时间大部分被浪费
- 晚期编辑的错误率更高 (78% vs 89%)
- 对于一些需要多步协调的复杂编辑, 最后 20 步的时间不够

**建议**: 考虑使用非均匀时间步长 (前面稀疏、后面密集), 或增加总步数。

### 3.2 Augmentation 敏感性

同一产物的不同 SMILES 排列, 结果可能完全相反:

| 产物 | aug_0 | aug_1 |
|:---:|:---|:---|
| 712 | 0/8 事件正确 → MISMATCH | 1/1 事件正确 → MATCH |
| 2253 | 0/3 事件正确 → MISMATCH | 4/4 事件正确 → MATCH |
| 4837 | 2/2 事件正确 → MATCH | 0/1 事件正确 → MISMATCH |

**问题 2: 模型对 SMILES 书写顺序敏感。** 同一个化学反应, 不同的 atom ordering 导致完全不同的编辑行为。这说明模型的 token-level 编辑策略没有学到真正的化学不变性。

**建议**: 训练时使用更多的 augmentation, 或在采样时对同一产物尝试多个 augmentation 取最佳结果。

### 3.3 事件数量差异巨大

```
产物 912:  1 个事件   → MATCH  (单 token INS)
产物 1828: 16-20 个事件 → MATCH  (大量编辑 + 自修正)
产物 712:  1 或 8 个事件 (取决于 augmentation)
```

**问题 3: 编辑效率差异大。** 产物 912 只需要 1 次编辑, 而产物 1828 需要 16-20 次。但两者都成功了——产物 1828 可能在做"试错-修正"循环。

**建议**: 分析产物 1828 的编辑序列, 看看模型在反复编辑什么。如果是同一位置反复修改, 说明模型的 token 预测不够确定。

### 3.4 事件正确但结果错误

查看产物 2006 aug_1: 4/5 事件正确 (80%), 但最终 MISMATCH。即使大部分编辑步骤都对, 只要 1 个关键 token 错了, 整个 SMILES 就不对。

**问题 4: 单 token 错误即可导致全局失败。** 当前的 event correctness 只检查位置+类型, 不检查 token。

**建议**: event correctness 增加 token 级别检查。

### 3.5 零事件样本

839 的 aug_1 和 1143 的 aug_0 产生了 0 个编辑事件, 被 HTML 跳过。模型对这两个输入"无动于衷"。

**问题 5: 模型可能完全静默。** 100 步输出和输入完全一样。

**建议**: 检查 first_step 可视化中这两个样本的模型速率, 看是否确实所有位置的 rate 都极低。

## 4. 改进建议优先级

| 优先级 | 建议 | 理由 |
|:---:|------|------|
| **高** | 增加 n_steps 或使用非均匀步长 | 46% 编辑挤在 t>0.8, 时间不够 |
| **高** | 多 augmentation 采样 + 投票 | 同一产物不同排列结果差异大 |
| **中** | Event correctness 增加 token 检查 | 4/5 正确却 MISMATCH |
| **中** | 分析产物 1828 的自修正行为 | 16-20 次编辑是否可压缩? |
| **低** | 检查零事件样本的 first_step | 确认是模型没信号还是采样没触发 |
