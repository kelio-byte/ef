# Fragment-level SPE checkpoint 评估总表（validation-dev）

记录日期：2026-08-19 UTC；最后补充：2026-08-20 的 M500 部分多 seed 复评，以及四组数据表示审计。
目的：把本轮所有**可直接横向比较**的 Atom / Full-SPE / SPE K=500 checkpoint 评估集中记录，并据此选择后续实验的临时 baseline。

## 固定评估口径

本表只纳入 `dev_unique1000_aug20` 上的 ordinary Euler 结果；不把 smoke、20% test 子集、不同 sampler（如 R9K1M2）混入同一张表，以免比较失真。

- 数据：1,000 个相同的 reaction blocks，每个保留 20 个 augmentation，共 20,000 个输入行。Atom、Full-SPE 与 K=500 使用各自 tokenizer 的投影文件；Full-SPE 与 K=500 的 manifest 记录了相同的原始 reaction indices。
- 推理：ordinary Euler，`N=9`、100 steps、cubic scheduler、seed 42、推理 batch size 32、augmentation 20、`n_best=10`、`process_number=12`。
- 每行评估均生成 180,000 条预测（20,000 输入 × 9 trajectories），并按 reaction block 聚合评分。
- `Invalid@1`：第 1 条采样轨迹的 invalid SMILES 比率，越低越好。
- `平均有效候选`：每个 reaction 的 20 × 9 = 180 条原始候选中，能被 RDKit canonicalize 的候选条数平均值；重复候选仍会计数。
- `平均去重候选`：同一 reaction 的全部有效候选 canonicalize 后再去重的数量；它衡量实际生成了多少个不同的化学候选。
- `9轨迹重合度`：任意两条轨迹各自跨 20 个 augmentation 的去重候选集合之间的 macro Jaccard 平均值，越低表示轨迹间越不重复、越高表示采样更容易收敛到相同候选。
- `采样时间`取 `sampling_metadata.json` 的 sampler elapsed time，不含可忽略的后处理/评分开销。

模型结构在各组中相同（hidden 256、10 layers、8 heads、FFN 2048）；但 Atom/早期 Full-SPE 使用训练 batch 128、`max_seq_len=256`，而本轮 Full-SPE B256 与 M500 使用训练 batch 256、`max_seq_len=96`。因此：**M500 与 Full-SPE B256 的同 step 比较是最严格的表示对照；Atom 对照是有价值的实用 baseline，但不是完全隔离 batch/训练样本预算的因果实验。**

## 分析

### 1. K=500 明显优于 Full-SPE：这是本轮最强、也最干净的证据

同为 B256、相同模型/训练超参、相同 400k step 时，M500 相比 Full-SPE：

- Top-1 `57.6 vs 56.3`（`+1.3 pp`）；Top-3/5/10 分别 `+3.0 / +3.0 / +3.5 pp`。
- Oracle `+1.3 pp`（`88.9 vs 87.6`），invalid 大幅降低 `7.260 pp`（`12.625% vs 19.885%`）。
- 平均有效候选增加 `13.053`，但平均去重候选减少 `7.601`。这说明 Full-SPE 的额外多样性中混有大量无效或低质量候选；单看去重候选数并不能代表覆盖质量更好。
- 采样时间只慢 `0.86 min`（约 3.6%），没有牺牲掉 Full-SPE 的主要速度优势。

对 reaction blocks 做 20,000 次 paired bootstrap（M500 400k − Full-SPE 400k）后，Top-3/5/10 的 95% CI 分别为 `+3.0 pp [ +1.2, +4.8 ]`、`+3.0 pp [ +1.2, +4.8 ]`、`+3.5 pp [ +1.7, +5.4 ]`。Top-1 的 `+1.3 pp [ -1.0, +3.6 ]` 与 Oracle 的 `+1.3 pp [ -0.2, +2.8 ]` 尚不足以排除 reaction-sampling 波动，但整体方向和 invalid 改善很明确。

结论：此前 Full-SPE 的问题不能简单归结为“fragment-level edit 不可行”。更符合数据的解释是：**3,002 条 merge rule 带来的超大词表和更高编辑密度过激；K=500 以略长序列换取更容易的 token/action 选择，收益大于速度损失。**

### 2. M500 的最优点并不单调：490K 是当前多 seed 的 Top-1 候选

外机密集 sweep 改写了“500K 的 raw Top-1 最高”的旧结论：490K 的 Top-1 为 **60.1%**、Top-5 为 **80.5%**、Oracle 为 **90.0%**，均为该 sweep 最高；且 Top-1 MaxFrag 也最高（64.8%）。相较主表中的 M500@500K，它的 Top-1 高 `0.2 pp`、Oracle 高 `0.3 pp`，但 Invalid@1 高 `0.605 pp`，Top-10 低 `0.6 pp`。

更完整的 trade-off 为：

- 490K：当前 3-seed 下的 Top-1 / Top-3 / Top-5 / Oracle 候选。
- 500K：已有完整 diagnostics 的实用候选，Top-10 为 84.3%，Invalid@1 为 12.245%。
- 510K：Top-3 最高（76.8%），但 invalid 明显较高（14.265%）。
- 520K / 530K：Top-10 并列最高（84.7%）；530K 的 Top-10 MaxFrag 最高（88.1%）。
- 600K：Top-3 MaxFrag 最高（80.5%），Invalid@1 最低（11.985%），但 Top-1 回落到 58.1%。

因此，不能再把 M500@500K 写成唯一最优 checkpoint。更新后的严谨表述是：**490K 已在配对 3-seed 下成为优先 Top-1/3/5/Oracle 的候选；500K 同样在配对 3-seed 下保有较低 invalid 与略高 Top-10。**若后续需要一个单一 baseline、且优化目标是首选排序准确率，则先用 490K；若目标是 Top-10 覆盖或更低 invalid，则保留 500K 作为对照。只有在 520K/530K checkpoint 可用时，才值得用相同 paired-seed 口径补测其中一个 Top-10 候选，而不是重新扫描所有 checkpoint。

### 3. 对 Atom baseline：M500 已展现很有价值的 Top-1 与效率收益，但还不能宣称全面替代

M500-500k 相对历史 Atom-600k baseline：

- Top-1 `+3.6 pp`（59.9 vs 56.3），paired bootstrap 95% CI 为 `[ +1.1, +6.1 ]`。
- Top-10 `+0.4 pp`；Top-3/5 分别 `-0.6/-0.2 pp`，Oracle `-0.5 pp`，这些差异的 95% CI 均跨过 0。
- invalid 仅高 `0.505 pp`（12.245% vs 11.740%），平均有效候选略低 `1.446`，但平均去重候选多 `1.818`。
- 采样从 58.21 分钟降至 24.47 分钟，约 **2.38× 更快**、节省 **58.0%** 时间。

这说明 M500 已不是“只换来速度、牺牲质量”的方案：它在 Top-1 与 Top-10 上至少和 Atom baseline 竞争力很强，同时保持约 2.4× 推理加速。仍需保守表述，因为 Atom 的 Top-3/5、Oracle、invalid 仍略好，而且 Atom 是 B128 历史训练，和 M500 B256 的训练预算不完全相同。

### 4. 继续训练到 600k 没有带来单调提升，出现候选重复增加的迹象

M500 从 350k 到 600k，invalid 大体下降（14.475% → 11.985%）、平均有效候选增加（154.089 → 158.319），但平均去重候选从 25.961 降至 22.649、9轨迹重合度从 33.409 升至 36.804。即后期输出更保守、更重复；这与 Top-1 在 500k 后回落、Top-3 却仍略升的现象一致。

因此目前没有理由仅因为“训练还没到 600k”就继续延长 M500 训练。更合理的是先在候选 checkpoint 间做采样重复验证，再决定是否需要改训练策略或 sampler。

### 5. Full-SPE 的后期 checkpoint 呈现指标取舍，而非稳定的单调增益

Full-SPE B256 的 470K、500K、550K、600K 已全部按同协议完成。不同 checkpoint 的强项分散：

- **470K：**Top-1 最高（56.4%），是优先首选排序时的 Full-SPE 候选。
- **500K：**Top-3/5/10 最高（73.6/79.0/81.5%），去重候选最多（30.833）且轨迹重合最低（29.427%），是偏 Top-K/多样性的候选；代价是 Top-1 降至 55.2%、Invalid@1 升至 17.755%。
- **600K：**在后期 checkpoint（470K 之后）中 Oracle 最高（88.8%），并且在全部 B256 checkpoint 中 Invalid@1 最低（15.400%）、有效候选最多（152.217）；相对 470K，它用 `-0.9 pp` Top-1 换得 `+0.8 pp` Oracle、`-1.090 pp` invalid 和更多有效候选。全程最高 Oracle 实际为 200K 的 89.0%，但其 Top-1 仅为 53.7%。600K 的 Top-3/5/10 为 72.4/77.3/81.4%，没有超过 500K 的 Top-K。
- **550K：**没有在上述核心目标上形成新的最优点。

因此，Full-SPE 没有一个 checkpoint 能同时支配 Top-1、Top-K、Oracle 与 invalid：470K 偏 Top-1，500K 偏 Top-K/多样性，600K 偏 Oracle/有效性。所有点仍只有 seed 42，不能把小于约 1 pp 的差异当作确定性的模型排序。完整曲线现已补齐，**不需要再重跑或继续训练 Full-SPE**；而且即使选择它最有利的指标，Full-SPE 后期点仍未显示追平 M500 强点的稳定趋势。

## 当前决策与下一步

1. **checkpoint 候选：**M500@490K（配对 3-seed 的 Top-1/3/5/Oracle 候选，首选排序任务的临时 baseline）、@500K（配对 3-seed 的较低 invalid / 较高 Top-10 备选）、@520K / @530K（仅单 seed 的 Top-10 候选）。当前不继续扩大 sweep。
2. **表示结论的公平补全：**Full-SPE 的 470K/500K/550K/600K 曲线已完成；不需要恢复训练或再重跑 600K。后续仅在确有必要时，用第二个 sampling seed 验证 470K、500K、600K 的取舍。
3. **最低成本确认：**490K 与 500K 均已完成 seed 42/7/123；若要继续，只在 520K/530K checkpoint 可用时对其中一个 Top-10 候选做同一 paired-seed 复评。用多 seed 平均 Top-1 选 checkpoint，并把 Oracle、Invalid、Top-10 作为约束，而不是继续扫更多训练步数。
4. **最终确认：**选定一个 checkpoint 后，才在未用于选择的完整 `src-test` / `tgt-test` 上跑一次同协议评估；不要继续用当前 dev-1000 之外的 test 子集调 checkpoint。
5. **报告边界：**paired bootstrap 只衡量这 1,000 个 reaction blocks 的抽样不确定性，不替代不同 sampling seed 的重复实验；目前结果足以支持 M500 继续作为主线，但尚不足以声称它在所有 Top-K/Oracle 指标上全面超过 Atom。

历史 20% test 子集、Full-SPE 600k 与 R9K1M2 的结果另见 [SPE_600k_experiment_report.md](SPE_600k_experiment_report.md)；它们的 test 范围或 sampler 不同，故没有混入本表。
