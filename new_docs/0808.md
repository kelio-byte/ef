# 2026-08-08 DGM 阶段汇报

## 0. 一句话结论

我们已经完成了从 reward、guidance 数据、guidance model 到 ordinary Euler 引导采样的第一版
闭环，并证明 Molecular Transformer 的正向 beam 重构 reward 有实际判别力；但是，当前
learned guidance 在两个互不重叠的 validation 子集上只表现出不稳定的局部收益，同时使采样
变慢约 47%，因此还不能把 DGM guidance 作为默认推理方法。

目前最稳定、可直接汇报的正向结果是：在冻结的 Euler 候选池上使用正向 beam reward 做
terminal reranking，validation-B 的 Top-1/3/10 从 58.5/77.5/88.5% 提升到
59.0/78.5/89.5%，Oracle 保持 91.0%。这证明 reward 方向有效，但它属于候选末端重排，不能
被表述为 learned DGM sampling 已经提升准确率。

## 1. DGM 方法介绍

### 1.1 我们希望解决什么问题

Edit Flows 学到的是一个条件生成分布：给定产物 `c`，生成可能的反应物 `y`。记模型终点
分布为：

```text
p1(y | c)
```

普通 Euler 采样忠实地从这个近似分布中生成候选，但模型概率高不等于候选一定正确、合法，
也不保证候选能通过正向反应重新生成输入产物。DGM 的目标是在不重新训练基础 Edit Flows
模型的前提下，使用一个外部 reward 把采样偏向更理想的终点分布。

给终点候选定义非负 reward `R(y, c)` 后，可以隐式定义：

```text
q1(y | c) ∝ p1(y | c) R(y, c)
```

因此：

```text
q1(y | c) / p1(y | c) = R(y, c) / Z(c)
```

其中 `Z(c)` 是只与 product 有关的归一化常数。我们不需要显式列出完整的 `q1`，只需要
reward 能让更好的候选获得更高权重。

### 1.2 为什么不能只在终点直接乘 reward

终点 reward 只告诉我们最终候选好不好，却没有直接告诉 Euler 在中间状态 `x_t` 的下一步
应该执行什么编辑。DGM 的核心是学习一个中间 guidance：估计从当前状态继续走下去能够获得
多大未来 reward，并据此重加权下一步离散转移。

直观地说，基础 Edit Flows 提供“这一步可能做哪些编辑及其概率”，guidance 则提供“哪些
编辑更可能通向高 reward 终点”。两者组合后再采样。

严格 DGM 需要与基础离散流的状态空间和转移坐标完全一致。当前 Edit Flows 同时存在插入、
删除、替换和变长序列，尤其连续 GAP 中的插入不总能唯一映射回 X-space 动作。审计发现
**89.735%** 的插入处于无法唯一反演的连续 GAP 情形。因此，我们当前实现应准确称为
**action-level approximate DGM**，不能称为 exact DGM。

### 1.3 DGM 的训练和推理 pipeline

当前 pipeline 如下：

1. 冻结已经训练好的 Edit Flows checkpoint，把它作为 proposal `pθ`。
2. 对每个 product 使用普通 Euler 独立采样多个 terminal reactants。
3. 用外部 reward 给每个 terminal 打分。
4. 根据 product、terminal 和随机时间 `t` 构造中间状态 `x_t`。
5. 从 `x_t → terminal` 的最优对齐中提取 insert/substitute/delete 动作监督。
6. 训练独立 guidance model `Hθ(product, x_t, t)`，使高 reward 路径上的动作获得更高正权重。
7. 推理时基础 Edit Flows 先输出动作 rate 和 token posterior，guidance 再使用 `H^β` 对动作
   重加权，最后仍按 ordinary Euler 走 100 步。

这里的 `β` 是 guidance 强度：`β=0` 必须严格退化为原始 Euler；`β` 越大，guidance 对基础
分布的影响越强。当前正式对照固定 `β=0.10`，没有在 validation 上无约束扫描。

## 2. DGM 落实到 Edit Flows 的具体适配

### 2.1 基础模型和采样器

- Edit Flows checkpoint：`new_checkpoints/checkpoint_step600000.pt`。
- checkpoint 的有效配置为 `use_origin_mask=False`。
- DGM 对照当前只接入 ordinary Euler；还没有接入 Euler-Beam。
- 所有准确率对照固定 `n_samples=3`、`n_steps=100`、`batch_size=64`、`seed=42`。
- guidance 关闭、常数 guidance 以及 `β=0` 的 identity 测试均已通过。

### 2.2 Reward：Molecular Transformer 正向 beam 重构

使用冻结的 Molecular Transformer：

```text
new_checkpoints/MIT_mixed_augm_model_average_20.pt
```

对一个逆合成候选 reactants，正向模型生成最多 5 个 product。如果原始输入 product 出现在
第 `k` 名，reward 为 `1/k`；如果 beam 中没有出现，reward 为 0：

```text
R = 1 / rank,  rank ∈ {1, 2, 3, 4, 5}
R = 0,         product 未被重构
```

该 reward 只读取候选反应物和输入 product，不读取逆合成 target。target 只在离线 validation
诊断中用于判断候选是否正确，因此 reward 本身没有泄漏答案。

我们还对候选反应物先做 canonicalization。等价的 SMILES 共用正向输入和缓存，既提高表示
不变性，也显著减少正向模型调用。

旧的 teacher-forced likelihood reward 判别力较弱，候选正确性 AUC 只有 **0.5639**，直接
重排还会损害准确率，因此已经不再作为主 reward。新的 canonical forward-beam reward 在
12,000 条 validation-B Euler 候选上的正确性 AUC 为 **0.6904**。

### 2.3 多终点 guidance 数据

旧 guidance 数据对每个 product 只有一个 terminal，再为同一个 terminal 采两个时间点。
40,003 个 product 组中没有任何组内 reward 变化，模型看不到“同一 product 下哪个后继更好”。

新数据固定：

```text
n_samples=4
time_samples=1
n_steps=100
```

即每个 product 由 ordinary Euler 生成 4 个独立 terminal，每个 terminal 只构造 1 个随机
中间时间。`x_t` 不是直接从 Euler trajectory 截取，而是通过 product-terminal 最优对齐和
Edit Flows 的 conditional coupling 重新采样得到。这与 Edit Flows 训练时的中间态语义一致，
但必须明确它不是实际 Euler 路径中曾经访问过的状态。

10,000 个 train products 共得到 40,000 条记录：

- 46.47% 的 product 组存在 reward 变化；
- 84.9% 的组包含多个不同 terminal；
- 平均 unique terminal 为 2.6519；
- 平均组内 reward range 为 0.4078。

这些统计与 1,000-product pilot 的 45.3%、85.2% 和 0.4085 一致，说明监督信号在扩大数据后
保持稳定。

### 2.4 Guidance model 和训练目标

当前 guidance 是一个独立的 `ProductConditionedGuidance`，约 **5.26M** 参数：

- hidden size 256；
- product encoder 2 层；
- current-state encoder 4 层；
- 8 个 attention heads；
- FFN 维度 1024；
- dropout/attention dropout 均为 0.1；
- 三个正值输出头分别预测 insert、substitute 和 delete 的 `H`。

基础 Edit Flows 和 Molecular Transformer 在 guidance 训练中都被冻结。Molecular Transformer
只提前生成 terminal reward，不参与每个 training step 的反向传播。

当前 action-level 目标把 `x_t → terminal` 对齐所需的动作标为 selected action。selected
action 的目标为 `reward + 1e-4`，其它合法动作的背景目标为 `1e-4`。主要损失是正 guidance
的 Bregman 目标：

```text
L(H, r) = H - r log H
```

insert/substitute/delete 分别计算 selected/background loss 后再平衡。优化器为 AdamW，学习率
`1e-4`，batch size 64。

当前缺点是：虽然数据已经为每个 product 提供 4 个 terminal，但训练 DataLoader 会把记录
完全打散，损失也只逐条拟合 reward，没有显式要求“同一 product 的高 reward terminal 路径
得分必须高于低 reward terminal 路径”。这正是下一阶段要解决的问题。

### 2.5 推理时如何作用于 Euler

模型在每个 Euler step 额外运行一次 guidance forward，产生正权重 `H`。当前默认的
`per_position` 模式先计算：

```text
guided action rate = base action rate × H^β
```

再把每个位置的总 edit rate 缩放回基础模型的原值。因此它能在同一位置内部重排插入、替换、
删除及 token，却不能把编辑强度从错误位置移动到正确位置。

我们实现并测试了 `per_sample`：只保持整条序列的总 edit rate，允许位置间转移强度。但它在
validation-A 上除了 Top-1 持平外，其余指标均弱于 `per_position`，而且没有速度收益，因此
默认仍为 `per_position`。

## 4. 可汇报的实验结果

### 4.1 数据划分和公平比较口径

以下结果来自 validation，不是最终 test：

- validation-A：original reaction 200–399，对应 `src-val.txt` 的行 `[4000, 8000)`；
- validation-B：original reaction 400–599，对应 `src-val.txt` 的行 `[8000, 12000)`；
- 每个 original reaction 有 20 条 augmentation；
- A 与 B 难度不同，只能在同一 split 内比较 baseline/guidance，不能把 A/B 的绝对值差异当成
  方法变化。

### 4.2 Molecular Transformer 自身是否可作为 reward model

在 validation-B 的 200 个已知反应上，正向 beam=5 的结果为：

| 指标 | 结果 |
|---|---:|
| Hit@1 | 71.0% |
| Hit@3 | 77.0% |
| Hit@5 | 79.0% |
| MRR | 0.7414 |
| wall | 12.0s |
| throughput | 16.65 reactions/s |

这说明 checkpoint 的方向、tokenization 和生成能力足以支撑 reward 实验，但不代表该模型对
所有错误逆合成候选都有完美判别能力。

### 4.3 Terminal forward-beam reranking

冻结 validation-B 的 12,000 条 ordinary Euler 候选，只改变终点排序：

| 方法 | Top-1 | Top-3 | Top-5 | Top-10 | Oracle | reward wall |
|---|---:|---:|---:|---:|---:|---:|
| 原始 Euler 排序 | 58.5% | 77.5% | 85.5% | 88.5% | 91.0% | 0s |
| canonical forward-beam rerank | **59.0%** | **78.5%** | 85.0% | **89.5%** | 91.0% | 117.6s |

canonicalization 把 8,131 个普通字符串归并为 2,332 个合法唯一结构，reward 计算相对原始
SMILES 模式提速 **3.03 倍**。正确候选的正向重构命中率为 81.86%，错误候选仍有 50.56%
会被重构，因此 reward 有效但不完美。Oracle 不变是合理的：reranking 只改已有候选的顺序，
不创造新候选。

### 4.4 Guidance 数据与训练效率

| 阶段 | 规模 | wall | 其它效率数据 |
|---|---:|---:|---|
| 10k terminal 生成 | 10,000 products / 40,000 records | 1,199.2s | 33.35 records/s；peak 0.68/4.60GB allocated/reserved |
| forward-beam reward | 40,000 records | 892.5s | 35,349 合法；21,749 unique canonical；复用 13,600 次 |
| guidance 训练 | 5,000 steps / 8 epochs | 970.1s | peak 2.05/3.31GB allocated/reserved |

10k 训练按最低 validation Bregman loss 选择 step 500：

- best validation loss：0.6674；
- held-out reward–selected-H Pearson：0.6707；
- 原有“各自状态/各自 terminal”口径下的 product 内 pair 排序准确率：60.19%；
- final step 5000 的 Pearson/排序为 0.6865/62.96%，但 validation loss 更差，因此没有事后
  更换主 checkpoint。

这些结果说明 guidance model 确实学到了 reward 方向，不说明它已经能稳定改善采样。

### 4.5 Learned guidance 的 ordinary Euler A/B 结果

固定 `β=0.10`、`per_position`、`n_samples=3`、`n_steps=100`、seed 42：

| split / 方法 | Top-1 | Top-2 | Top-3 | Top-5 | Top-10 | Oracle | sampling wall |
|---|---:|---:|---:|---:|---:|---:|---:|
| validation-A baseline | 51.0% | 66.5% | 72.0% | 77.0% | 83.5% | 86.5% | 253.0s |
| validation-A 10k guidance | **53.0%** | 66.5% | 71.5% | **78.5%** | 83.5% | 85.5% | 371s |
| validation-B baseline | **58.5%** | 73.0% | 77.5% | 85.5% | 88.5% | 91.0% | 264.4s |
| validation-B 10k guidance | 56.5% | **75.0%** | **80.0%** | **86.0%** | 88.5% | **91.5%** | 388s |

> 注意：上表 validation-B guidance 的 Top-2 为 **75.0%**。该单元格中的加粗只表示同 split
> 内数值更高，不代表整体方法通过。

结论是混合的：A 的 Top-1 提升 2 点但 Oracle 下降 1 点；B 的 Top-1 下降 2 点，但 Top-2/3
和 Oracle 有提升。两个 split 的采样时间都增加约 **47%**，原因是每个 Euler step 多执行一次
guidance model forward。

`per_sample` 在 validation-A 的 Top-1/2/3/5/10 为
53.0/64.0/71.0/77.5/82.0%，Oracle 84.5%，除 Top-1 与 `per_position` 持平外，其余均更差，
因此没有继续运行 validation-B。

## 5. 当前能够和不能够得出的结论

可以汇报：

1. 已经完整搭建 action-level approximate DGM 的数据、训练和 Euler 推理闭环。
2. Molecular Transformer forward-beam reward 明显优于旧 likelihood reward，并且 terminal
   reranking 在固定 validation-B 候选池上带来小幅 Top-k 提升。
3. 多终点数据修复了旧数据完全没有 product 内 reward 对比的关键问题。
4. guidance model 在 held-out 数据上能学习 reward 方向，并会改变有意义的候选覆盖。
5. 当前 learned guidance 只带来不稳定的局部收益，尚未达到默认方法门槛。

不能声称：

1. 不能说 DGM 已经稳定提高 Edit Flows 的总体准确率。
2. 不能把 terminal reranking 的提升说成 learned guidance sampling 的提升。
3. 不能把当前 action-level 适配称为 exact DGM。
4. 不能根据这 200+200 个 validation 反应宣称完整 test 指标。
5. 不能说 DGM 把推理从 100 步变成了 1 步；当前仍使用 100-step Euler。

## 6. 下一步研究方向

下一步选择继续改进 learned guidance，而不是直接扩大 full-40k 或接 Euler-Beam。核心改动是：

当前 P0–P5 的代码实现、CPU/CUDA/CLI smoke 和 1k pilot 已完成；pairwise pilot 未通过。P5b
审计发现现有 multi-terminal records 的 4 条记录并不共享 `(x_t,t)`：validation-200 只有 23/200
组的 state 全相同，所有组的 time 都不同。下一步先修正 shared-anchor 数据生成并做结构审计，在此
之前不启动 10k 或准确率采样。

P5c 已完成 continuation 最小实现和 CUDA smoke：真实 checkpoint 下 4 products、2 children、4
steps 为 0.799s，4/4 组 state/time 完全相同，且每组 terminal 均出现两个不同结果。下一步是用
该路径生成隔离的 1k shared-anchor 数据、附加 forward-beam reward，再重新做 pairwise pilot。

1. 使用 group-aware batch，保证同一 product 的 4 个 terminal 同时进入 batch；
2. 在完全相同的 `(product, anchor x_t, t)` 上，分别计算通向多个 terminal 的动作集合得分；
3. 显式加入 product 内 pairwise-ranking loss，让高 reward terminal 的动作得分高于低 reward
   terminal；
4. Bregman action loss 继续作为辅助约束，避免只学排序而失去 guidance 数值校准；
5. 用预先声明的 validation 排序指标和 Bregman guardrail 选 checkpoint；
6. 先做 1k pilot，只有通过门槛才扩大到 10k；只有 ordinary Euler 在 A/B 同时保持 Top-1
   并改善 Top-3/10 或 Oracle，才考虑接 Euler-Beam。
