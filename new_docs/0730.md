## 1. Bug 修复

### 1.1 Rate Correction 数值爆炸 (P0)

`edit_flows/sampling/euler.py` 中 `sample_euler` 在 cubic→linear scheduler 切换时，`k_train.clamp_min(1e-12)` 在 t=0 处导致 rate 放大 1e12 倍。

```
k_train (cubic, t=0) = 0 → clamp(0, 1e-12) = 1e-12
k_sample (linear, t=0) = 1
ratio = 1 / 1e-12 = 1e12
log_correction = ln(1e12) ≈ +27.6
model log_rates -19 → +8.6 → 每位置 100% 编辑概率 → 随机垃圾 token
```

**修复**: `clamp_min(1e-12)` → `clamp_min(1e-2)` (两处: `sample_euler` + `sample_euler_with_first_step_intervention`)

**同类修复**: `visualize_first_step.py` 中 oracle rate de-scaling 的 `clamp_min(1e-12)` 同样修复。

## 3. Euler-Beam 设计与实现

### 3.1 动机

Euler 采样问题:
- 方差大 (同一产物 10 次采样命中率 0~3/10)
- 可能完全静默 (100 步 0 编辑)
- 单条轨迹无法利用共识

### 3.2 核心设计

```
每步:
  1. 收集所有活跃分支 (t < 1.0)
  2. 批量 GPU 前向 (一次 model forward)
  3. 批量随机采样 (一次 _sample_edit_actions)
  4. 逐分支: 提取动作、计分、应用编辑 (CPU 轻量循环)
  5. 逐样本: 去重 → 排序 (-path_log_p, weight) → Top-K 剪枝 → 不足时分裂

最后: 返回每条样本的最优分支
```

### 3.3 文件

| 文件 | 说明 |
|------|------|
| `edit_flows/sampling/euler_beam.py` | 核心实现, 中文注释 |
| `scripts/sample_retro.py` | 集成 `--sampler euler_beam` |
| `scripts/visualize_trajectory.py` | 集成 `--n_branches` (event recording 待补) |

### 3.4 参数命名

| 参数 | 含义 |
|:---|:---|
| `--n_branches` | 一次搜索内部并行分支数 (K 条 Euler 轨迹) |
| `--n_runs` | 每个产物独立搜索次数 (= Euler 的 `--n_samples`) |
| `--beam_size` | beam_edit 采样器专用 (保持不变) |

### 3.5 与 Euler 的输出对齐

```
Euler:       n_samples=3 → 3 行/产物
Euler-Beam:  n_runs=3    → 3 行/产物

score.py 参数完全一致: --augmentation 20 --beam_size 3
```

### 3.6 性能优化

修复前: 每步 ~800 次独立 GPU 调用 (`_sample_edit_actions` × N 分支)
修复后: 每步 1 次批量 GPU 调用 (所有分支一次处理)

### 3.7 当前局限

| 问题 | 状态 |
|------|------|
| Event recording | 未实现 (可视化显示 "0 edit events") |
| 大规模验证 | 待跑 GPU |
| 排序策略 | `(-path_log_p, weight)` 待验证效果 |
| 分裂权重衰减 | 固定 0.5, 未调优 |

## 4. 实验分析

### 4.1 10 轮 × 20 augs 稳定性测试

- 总采样 20,000 次, per-sample 命中率 26.3%
- 轮间标准差 0.9% (极稳定)
- 9/10 产物在 200 次机会下 Top-1 ACC ≈ 100%
- 产物 1143 是唯一例外 (仅 70%)

### 4.2 关键发现

- **Augmentation 敏感性**: 产物 4837 CV=161%, 不同 SMILES 排列命中率差 10 倍
- **失败时编辑更多**: 产物 204 成功需 3.7 次编辑, 失败需 6.6 次 (模型在"挣扎")
- **编辑集中晚期**: 46% 事件挤在 t>0.8
- **Event correctness 盲区**: 4/4 events "correct" 却 MISMATCH (不检查 token)
- **纯 DELETE 操作全败**: 产物 712 的 `= → 无` 模型完全不会

## 5. Euler 采样原理

```
每步:
  模型输出: log_rates (每个位置 INS/SUB/DEL 的速率)
           log_ins_probs (如果 INSERT, 插哪个 token 的概率分布)
           log_sub_probs (如果 SUB, 换哪个 token 的概率分布)

  采样: prob = 1 - exp(-h × rate)     ← 速率 → 概率
       rand() < prob → 触发编辑       ← 随机掷骰子
       multinomial(probs) → 选 token  ← 按概率分布选 token

  应用: 先 SUB (换 token, 长度不变)
        再 INS/DEL (增删, 长度变化)

  t += adapt_h (自适应步长)
```

Euler 指的是这个"用随机采样离散化连续速率的数值方法"。
