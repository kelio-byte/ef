# Stage1 S2：把化学反应位置对应到 M500 序列位置

日期：2026-08-24

## 这一步到底在做什么

这一步**没有训练模型，也没有跑准确率推理**。它只回答一个前提问题：

> 已知一条反应真正发生化学变化的位置后，我们能否在模型实际看到的 M500 token 序列中，稳定地找到对应的位置？

这是后续 B1 实验的必要前提。若化学上的位置无法可靠对应到 M500 序列位置，那么“引导模型在反应中心附近编辑”就没有可操作的含义。

本检查在训练集固定抽取的 1,000 条反应上完成；每条保留全部 20 种 R-SMILES 写法，共 20,000 个序列视图。所有 20,000 个视图都成功完成了这个对应。

## 先把几个词说清楚

### 1. 什么是“反应中心”

反应中心不是固定的一个原子，而是**产物中发生化学变化的一小块区域**。我们利用原子映射，将产物和真实反应物逐原子、逐键比较，把下面三种变化所在的产物原子标出来：

- 一条键断开、形成，或键级/立体化学发生变化：这条键的两个端点都属于中心；
- 某个保留原子的电荷、氢数、手性、芳香性等属性发生变化：该原子属于中心；
- 反应物中新添的一段片段接到产物中的某个原子上：这个“接入口”的产物原子属于中心。

因此，一个中心区域可以只有一个原子，也可以包含多个相连原子。例如，若产物中 `B=C` 在反应物中变成 `B-C`，那么 `B` 和 `C` 共同构成一个中心区域，而不是二选一。

在本次 1,000 条反应样本中，964 条有 1 个彼此分开的中心区域，30 条有 2 个，6 条有 3 个；没有超过 3 个的样本。这里的“多个中心”指产物中相隔较远、彼此独立的化学变化区域。

### 2. 什么是“一跳邻域”和 `radius-1`

这里的“一跳”是**分子图上的一根化学键**，不是字符串里相邻的一个字符。

仍以局部结构 `A—B=C—D—E` 为例：若 `B=C` 是反应中心，

- `radius-0`：只有中心本身，即 `B`、`C`；
- `radius-1`：中心加上与中心直接成键的原子，即 `A`、`B`、`C`、`D`；
- `radius-2`：再向外多走一根键，例如还会包含 `E`。

选择 `radius-1` 的本意不是说邻居也一定发生化学变化，而是给字符串编辑留出一点表示上的余量：一个化学变化在 R-SMILES / SPE 中可能需要改到中心旁的 token 或插入边界。

### 3. 什么是 `radius-1 token`

M500 的一个 token 是一个 SMILES 片段，可能覆盖 1 个原子，也可能经 SPE 合并后覆盖多个原子。我们给每个 token 保留它覆盖哪些产物原子的记录。

若一个 token 覆盖的任意原子属于上面的 `radius-1` 区域，就把它称为 **`radius-1 token`**。它不是“token 离另一个 token 一步远”，而是“token 所含原子离反应中心至多隔一根化学键”。

继续用上面的例子：假设若干 M500 token 分别覆盖 `A`、`B/C`、`D`、`E`，那么前三个都是 `radius-1 token`，覆盖 `E` 的 token 不是。

### 4. 什么是 `syntax-only token`

SMILES 中不只有原子，还有括号、键符号、环号、点号等**描述写法的符号**。只由这类符号构成、没有覆盖任何原子的 M500 token，称为 `syntax-only token`。例如一个单独的括号 token 没有对应的化学原子。

它仍然是模型需要编辑的序列位置，所以不能直接丢掉。为了在统计和 B1 中给它定位，我们采用固定规则：把它临时关联到字符串左右最近的原子 token。这个规则只是“给语法位置找附近化学位置”的办法，**不表示括号或环号本身是反应中心原子**。

在本次样本中，93.655% 的 M500 token 直接包含原子，6.345% 是这类纯语法 token；按上述固定规则后，全部 token 都能得到一个附近的分子图位置。

## 一个具体的小例子

假设产物局部为 `A—B=C—D—E`，真实反应使 `B=C` 变为 `B-C`。

1. 从原子映射比较得到：`B`、`C` 是反应中心。
2. 在产物图上扩一根键：`A`、`D` 是中心的一跳邻居。
3. M500 token 若覆盖 `B/C`，分数最高；覆盖 `A` 或 `D`，分数次高；覆盖 `E`，分数为零。
4. 若目标序列要在 `B/C` 附近新增一个反应物片段，我们不把新增片段误说成“产物中已有的中心 token”，而是检查它**从哪个 token 间隙插入**；该间隙左右的原子若靠近 `B/C`，就视为靠近中心。

这个例子也说明：实际发生的字符串编辑位置不必与中心原子一一重合。化学中心是图上的小区域；M500 编辑的是该区域在一种字符串写法中的表示。

## `28.737% / 91.088% / 96.343%` 到底是什么意思

这三个数字来自对已对齐训练样本的**静态回看**，不是模型预测准确率。

| 统计 | 白话含义 |
|---|---|
| `28.737%` | 全部 M500 token 中，只有约 29% 位于“中心本身或其一跳邻居”这一小块区域。 |
| `91.088%` | 回看真实目标所要求的已有-token 修改/删除位置时，约 91% 落在这 29% 的小区域内。 |
| `96.343%` | 回看真实目标需要新增片段时，约 96% 的插入入口位于这块小区域旁。 |

更直白地说：如果随机从整条序列找位置，要看 100 个 token；如果先看中心及一跳邻域，只需看约 29 个 token，却已经覆盖了绝大多数真实编辑入口。

这不表示“91% 的模型编辑会正确”，也不表示“所有编辑都必须在中心”。它只说明：**在数据的真实编辑方案中，编辑位置高度集中在化学变化附近。** 仍有约 8.9% 的已有-token 编辑和约 3.7% 的插入入口在 `radius-1` 外，因此中心只能是软提示，不能被当作硬约束。

## 本次实际怎样完成对应

1. 用原子映射的原始反应确定化学中心；
2. 对现有 product R-SMILES 按 `SPE_ChEMBL.txt` 前 500 条规则重放同一套 SmilesPE 合并，不重新训练 tokenizer；
3. 每次合并都把子 token 覆盖的原子集合合并起来，因此最终 M500 token 仍知道自己来自哪些原子；
4. 用产物图计算 token / 插入边界到中心的最短化学键距离；
5. 将真实对齐中的 SUB、DEL 位置和插入入口与上述区域比较，得到覆盖率。

这里统计的“已有-token 编辑”是目标要求替换或删除已有 token 的位置；“插入入口”是目标要求在两段已有 token 之间添加新片段的边界。连续插入的一整段只算一个入口，避免长片段被重复计数。

## 映射的稳健性检查

原子 map 被移除后，对称产物可能有多个同样合法的图对应关系。我们保留所有对称等价位置的并集，避免中心位置取决于 RDKit 恰好先返回哪一个匹配。20,000 个视图中有 16,200 个存在多个同构；这不是失败。只有 1 个反应的 20 个视图达到预设 `max_isomorphisms=1024` 上限，已单独标记。

抽样中 995 条使用严格立体匹配，5 条使用无立体 fallback；另有 5 条属于重复 canonical key 的多义 occurrence。排除这 10 条后，核心结论几乎不变：

| 指标 | 全部 1,000 | 严格且唯一的 990 |
|---|---:|---:|
| `radius-1` token 覆盖 | 28.737% | 28.664% |
| 已有-token 编辑覆盖 | 91.088% | 90.992% |
| 插入入口覆盖 | 96.343% | 96.324% |
