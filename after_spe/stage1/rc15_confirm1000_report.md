# RC1.5 独立确认：3 条中心引导 + 6 条普通 Euler

日期：2026-08-24
状态：**已完成；不通过进入中心预测器的门槛。** 本次结果保留“真实反应中心能改善首步”的机制证据，但不支持把 `3+6` 混合规则继续发展为可部署的 product-only 中心预测器。

## 为什么要做这次确认

全中心引导 B1 在 dev 和独立 confirm 上都提高了 Top-1，但九条轨迹都被推向同一小块区域，真正不同的候选会减少。为缓解这个问题，RC1.5 固定采用：

- 3 条轨迹：只在第一次实际编辑前，软性偏向真实反应中心；
- 6 条轨迹：完全普通的 Euler；
- 所有轨迹第一次实际编辑后：都恢复普通 Euler。

在 dev-1000 上，这个 `3+6` 方案看起来兼顾了 Top-1 与候选覆盖。此次在此前未用于选择该设计的 confirm-1000 上原样复核：**不改 checkpoint、倍率、轨迹配比、seed、步数或评分规则。**

真实中心来自答案侧，因此 B1 和 RC1.5 都只是 oracle 上界实验，不能直接部署。

## 固定实验设置与正确性检查

| 项目 | 设置 |
|---|---|
| 模型 | global R-SMILES 的 `SPE-M500@490K` |
| checkpoint | `new_checkpoints/spe_m500_checkpoints/checkpoint_step490000.pt` |
| 数据 | `confirm_unique1000_aug20`：1,000 条独立反应 × 20 个 augmentation = 20,000 输入行 |
| 采样 | Euler，9 条轨迹，100 steps，seed 42，batch size 32 |
| 每组候选 | 180,000 条；按每个 reaction 聚合 180 条候选后评分 |
| B0 | 9 条普通 Euler |
| B1 | 9 条真实中心引导轨迹（oracle） |
| RC1.5 | 3 条真实中心引导 + 6 条普通 Euler（oracle） |

B0、B0-trace、B1 复用已完成的同协议 confirm 输出；运行脚本先核验 input hash、checkpoint、采样参数、候选行数，并逐字节验证 B0 与仅记录事件的 B0-trace 相同。本次只新生成 RC1.5。

| 完整性检查 | 结果 |
|---|---:|
| RC1.5 候选数 | 180,000（20,000 × 9） |
| 中心引导 / 普通轨迹 | 60,000 / 120,000 |
| 有首次编辑的引导 / 普通轨迹 | 58,026 / 116,036 |
| 无首次编辑的引导 / 普通轨迹 | 1,974 / 3,964 |
| 普通轨迹被位置重加权 | 0 条 |
| 中心引导轨迹首次事件被位置重加权 | 58,026 条 |
| 同一操作总编辑强度的最大相对误差 | `2.46e-6` |
| B0 与 B0-trace | 180,000 条预测逐字节一致 |

因此 6 条普通轨迹没有受到中心权重影响；差异只来自预定的 3 条轨迹在首次编辑前的位置偏向。

以 reaction 为统计单位、20 个 augmentation 只用于候选聚合，进行 10,000 次 paired bootstrap：

| RC1.5 − B0 | 点估计 | 95% 区间 |
|---|---:|---:|
| Top-1 | +0.7 pp | [-0.7, +2.2] pp |
| Top-3 | -0.7 pp | [-2.1, +0.7] pp |
| Top-5 | -1.0 pp | [-2.6, +0.5] pp |
| Top-10 | -0.5 pp | [-1.8, +0.9] pp |
| Oracle-any | -0.7 pp | [-1.9, +0.5] pp |

RC1.5 的确比全 B1 保留更多不同候选：`RC1.5 − B1 = +0.296`，95% 区间 `[+0.018, +0.582]`。但它也失去了 B1 的大部分 Top-k 优势；B1 相对 RC1.5 的 Top-1/3/5/10/Oracle 点估计分别为 `+0.8/+1.3/+1.3/+0.6/+0.8 pp`，相应区间仍均覆盖 0。

## 首次编辑是否按设计工作

“更接近目标”指首次非空 Euler 步中的全部实际编辑应用后，当前 token 序列到真实目标的 token 编辑距离是否变小；它不把某一种编辑顺序武断认定为唯一正确路径。

| 轨迹集合 | 首次编辑在真实中心或一跳邻域 | 首步后更接近目标 | 首步后更远离目标 | 平均 token 距离改善 |
|---|---:|---:|---:|---:|
| B0-trace | 84.53% | 66.14% | 18.43% | +0.482 |
| 全 B1 | 88.06% | 67.96% | 15.98% | +0.525 |
| RC1.5 全部 9 条 | 85.67% | 66.71% | 17.67% | +0.495 |
| RC1.5 的 3 条中心引导 | 88.25% | 67.83% | 16.01% | +0.523 |
| RC1.5 的 6 条普通 Euler | 84.38% | 66.15% | 18.50% | +0.481 |

这说明实现和局部机制都正常：3 条引导轨迹几乎复现全 B1 的首步改善，6 条普通轨迹几乎复现 B0。问题不在于“偏向没有生效”，而在于这种混合在独立 reaction 上没有把局部改善稳定地转化成更好的候选覆盖。

## 与 dev 的对照，以及最终判断

| split | RC1.5 − B0 Top-1 | Top-3 | Top-5 | Top-10 | Oracle | 结论 |
|---|---:|---:|---:|---:|---:|---|
| dev-1000 | +1.1 pp | +0.6 pp | +0.6 pp | +0.5 pp | +0.2 pp | 点估计全面正向，值得确认 |
| confirm-1000 | +0.7 pp | -0.7 pp | -1.0 pp | -0.5 pp | -0.7 pp | 只保留 Top-1 的弱正向，覆盖指标反向 |

预先设定的继续门槛是：**Top-1 不下降，且 Top-k/Oracle/unique 不出现明确损失。** confirm 的 Top-1 仍为正，但 Top-3/5/10/Oracle 全部转为负向点估计，所有区间也覆盖 0。因此不能把 dev 的结果解释为稳定的“兼顾准确率和覆盖”的设计收益。

最终结论分两层：

1. **保留机制结论。** 真实反应中心会把首次编辑更常推到化学变化附近，并使首步更常接近目标；全 B1 在两个 split 的 Top-1 也都高于 B0。
2. **停止方法分支。** 当前 `3+6` 轨迹混合没有在独立 confirm 上满足端到端覆盖门槛。由于它本身已使用真实答案中的中心，训练一个信息更弱的 product-only predictor 没有充分依据；不训练 predictor、不继续扫描倍率或轨迹比例、不使用 final/test 继续挑选。

因此后续推理/训练改进的正式 baseline 仍是：

```text
global R-SMILES + SPE-M500@490K + ordinary Euler N=9, 100 steps
```

反应中心资料和本次 oracle 结果保留为已验证的机制诊断；如未来重启该方向，应有新的、独立于当前 `3+6` 局部 bias 的设计理由，而不是继续在相同 split 上微调。
